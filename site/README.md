# אתר הכרויות — MVP

אתר הכרויות בעברית (RTL): פרופילים, חיפוש לפי עיר/גיל/סוג קשר, לייקים והתאמות,
צ'אט בזמן אמת עם שליחת תמונות, פאנל ניהול ומודרציה, ותוכנית שיווק שותפים.

**סטאק:** Next.js 16 (App Router) · TypeScript · PostgreSQL + Prisma · Tailwind v4 · SSE לצ'אט · sharp לתמונות

---

## הרצה מקומית

```bash
# 1. תלויות
npm install

# 2. משתני סביבה
cp .env.example .env
#    לערוך את DATABASE_URL ואת AUTH_SECRET (לפחות 32 תווים)

# 3. סכמה + נתוני דמו
npm run db:push
npm run db:seed

# 4. הרצה
npm run dev          # http://localhost:3000
```

### משתמשי דמו (אחרי `db:seed`)

| משתמש | אימייל | סיסמה |
|---|---|---|
| מנהל ראשי | `admin@example.com` | `demo1234` |
| משתמשי דמו | `noa@` `yossi@` `maya@` `avi@` `dana@` `omer@` `shirin@` `eitan@` `example.com` | `demo1234` |

`dana@example.com` היא שותפה מאושרת עם הקוד `dana` — הקישור שלה הוא `/r/dana`.

## מה יש במערכת

### פרופילים וחיפוש
- הרשמה עם חסימת גיל: מתחת ל-18 נדחית בשרת, לא רק בטופס.
- פרופיל: שם, גיל, מגדר, עיר, סוג הקשר שמחפשים, טקסט חופשי, גובה, ילדים, עישון.
- חיפוש (`/search`): מגדר · עיר · טווח גילאים · סוג קשר · "עם תמונה בלבד", עם עמודים.
  ברירת המחדל של הסינון נלקחת מהעדפות הפרופיל של המשתמש.
- מי שדילגתם עליו, מי שחסמתם ומי שחסם אתכם — לא מופיעים בתוצאות.

### תמונות
- העלאה עוברת דרך `sharp`: אימות שזו באמת תמונה, יישור לפי EXIF, הקטנה והמרה ל-WebP.
  **כל המטא-דאטה נמחקת בתהליך, כולל מיקום GPS.**
- תמונות פרופיל נכנסות לתור אישור ומוצגות רק אחרי אישור הצוות.
- תמונות בצ'אט מוצגות מיד למשתתפים בלבד, וניתנות לדיווח.
- אין גישה ישירה לקבצים: הכול עובר דרך `/api/media/[id]` שבודק הרשאה בכל בקשה
  (בעלים / צוות / פרופיל מאושר וגלוי / משתתף בשיחה).

### התאמות וצ'אט
- לייק הדדי יוצר התאמה ופותח שיחה. **אי אפשר לשלוח הודעה בלי התאמה** — זה מצמצם הטרדות.
- צ'אט בזמן אמת מעל SSE (`/api/stream`): חיבור אחד למשתמש שמעביר הודעות חדשות,
  סימוני "נקרא" והתראות התאמה.
- שליחת תמונות בשיחה, אישורי קריאה, וחסימה/דיווח מתוך השיחה.

### בטיחות ומודרציה
- דיווח על משתמש, הודעה או תמונה · חסימה דו-כיוונית.
- פאנל `/admin`: סקירת מדדים, תור אישור תמונות, טיפול בדיווחים, ניהול משתמשים
  (השעיה/חסימה/החזרת גישה), וניהול שותפים.
- שתי רמות הרשאה: `MODERATOR` (תמונות, דיווחים, משתמשים) ו-`ADMIN` (גם שותפים ועמלות).
- הגבלת קצב על הרשמה, כניסה, העלאות, לייקים, הודעות ודיווחים.

### שיווק שותפים
- הצטרפות עצמית ב-`/affiliate`, אישור ידני של מנהל.
- קישור אישי `/r/<קוד>` (אפשר `?to=/search`) → רישום קליק + עוגיית ייחוס ל-30 יום.
- בהרשמה נוצרת רשומת `Referral`. הפניה עצמית לא מזכה בעמלה.
- שני סוגי עמלה: בונוס הרשמה חד-פעמי, ואחוז מכל תשלום של המופנה.
  האחוז והבונוס ניתנים לעריכה לכל שותף בנפרד.
- לוח בקרה לשותף: קליקים, הרשמות, עמלות לפי סטטוס.
- זרימת סטטוסים: `PENDING → APPROVED → PAID`, עם `REVERSED` לביטול.

## מה עוד נדרש לפני עלייה לאוויר

הדברים האלה מכוונים במפורש לפיתוח מקומי וצריכים החלפה בפרודקשן:

1. **אחסון תמונות** — כרגע דיסק מקומי (`UPLOAD_DIR`). להחליף ל-S3/R2 עם URL חתום.
   נקודת השינוי היחידה היא `src/lib/storage.ts`.
2. **סליקה** — `/api/payments` יוצר תשלום מדומה בלי חיוב אמיתי, רק כדי להריץ את
   שרשרת העמלות. לחבר ספק סליקה (למשל Stripe/Tranzila) ולהפעיל את
   `commissionForPayment` מתוך webhook מאומת, לא מהדפדפן.
3. **צ'אט בכמה מופעים** — `src/lib/events.ts` הוא אפיק בזיכרון התהליך. עם יותר
   ממופע שרת אחד צריך Redis pub/sub או Postgres LISTEN/NOTIFY.
4. **הגבלת קצב** — `rateLimit` ב-`src/lib/api.ts` שומרת בזיכרון. להחליף ל-Redis.
5. **אימות אימייל ואיפוס סיסמה** — עוד לא ממומשים.
6. **מודרציה אוטומטית** — כרגע כל תמונה נבדקת ידנית. בקנה מידה גדול כדאי סינון
   תוכן אוטומטי כשלב ראשון, ואדם רק על מה שמסומן.
7. **דרישות רגולציה** — תנאי שימוש, מדיניות פרטיות ומנגנון מחיקת חשבון ונתונים
   (זכות למחיקה). המודל תומך במחיקה מדורגת, אבל אין עדיין מסך למשתמש.
8. **`AUTH_SECRET`** — חובה להחליף למחרוזת אקראית ארוכה; החלפתה מנתקת את כל המשתמשים.

## הערה על "סוכנים באתר"

לא מימשתי מפעילי צ'אט/סוכנים שמנהלים שיחות מול משתמשים, כי לא סיכמנו למה
הכוונה. אם הכוונה לצוות תמיכה ומודרציה — זה כבר קיים דרך תפקידי
`MODERATOR`/`ADMIN`. אם הכוונה לשכבת סוכנים בתוכנית השותפים (סוכן שמגייס
אפיליאייטס ומקבל אחוז מהם) — זו תוספת קלה על המודל הקיים. ואם הכוונה לנציגים
שמתכתבים עם משתמשים, חשוב שיהיו מסומנים ככאלה בממשק ולא יוצגו כפרופילים
אמיתיים — התחזות היא הפרה של חוקי הגנת הצרכן ושל תנאי חנויות האפליקציות.
